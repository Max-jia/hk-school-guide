# 移动端性能修订与本地验收

日期：2026年11月19日。状态：本地预览，未提交、未推送、未部署。

## 本轮改了什么

1. 共用导航改用已核对的繁简固定文案和轻量网址工具，报告数量在构建时从原有三个报告列表生成。浏览器不再为了导航文字及数量下载整份报告摘要和转换字典。
2. 博客的文案、分类、排序日期及专题卡片在构建时处理，放入可缓存脚本；全部文章仍在初始HTML中。完整检索索引及小型繁转简搜索模块在输入文字后才加载。载入失败可重试，文章仍可按分类浏览。
3. 其他仍需转换的页面，仅在用到相应方向时建立转换器。保留原有香港字形修正、专名处理及检索规则。
4. 页尾两张320×320贴图补齐尺寸，使用延迟加载和异步解码。图片、替代说明和链接均保留。手机博客首屏实测不再请求这两张图，少传输约110KB。

统计、广告和同意管理的配置、标识及加载策略保持原样。没有改学校正文、收费、日期、排名或其他学校事实。

## 已通过的回归

- 两个独立本地生产构建使用同一锁文件及Next.js 16.3.0 Turbopack。修改前基线是本分支HEAD 42a0ae50；本轮没有重新获取线上部署源码，比较结论仅针对本地前后版本。
- 5,428个静态HTML页面的可抓取文字、标题层级、元数据、canonical、hreflang、链接、结构化数据、表单说明和图片来源/替代说明一致。构建生成5,439项页面/路由输出；两者不是同一统计口径。
- sitemap与robots产物逐字节相同；原有目录数据与来源保持原样。
- 30项浏览器检查通过：繁简各8种查询与原版的结果及JSON-LD一致，包含繁简混写、英文及无结果查询；检查375/768/1440宽度、手机菜单、完整目录搜索、筛选弹窗和两校比较。没有捕获到应用异常。
- 按需检索另通过3项检查：首屏不请求索引、网络失败仍可浏览文章并提示重试、重试后恢复结果。
- 固定导航64项繁简文案对比通过，291条转换输入及搜索归一化与原版相同；报告数239、索引175条均与原始数据列表一致。
- 类型检查通过；本批代码ESLint无错误。页尾沿用的两个普通img仍有Next.js优化建议，已补尺寸与延迟加载；未引入图片优化服务。

## 手机实验室结果

每个版本、每条路径测3次，取中位数，前后顺序轮换。独立Chrome临时配置，Lighthouse 13.6.0，模拟手机慢速4G与4倍CPU减速。为防止测试流量写入统计及减少广告波动，两边都阻断HTTPS第三方请求。**这不是线上完整页面的PSI分数，不能与11月17日的生产测量直接比较，也不代表真实用户Core Web Vitals达标。**

| 页面 | 脚本阻塞TBT：前→后 | JS执行时间：前→后 | LCP：前→后 |
|---|---:|---:|---:|
| 简体博客列表 | 79.5→12.5毫秒 | 350.9→151.5毫秒 | 1.534→1.535秒 |
| 简体幼稚园目录 | 68.5→19.5毫秒 | 362.2→266.3毫秒 | 1.533→1.534秒 |
| 繁体幼稚园目录 | 86.1→124.0毫秒 | 371.5→359.5毫秒 | 1.533→1.534秒 |

简体两页的阻塞时间下降，首屏时间基本持平。繁体目录的阻塞中位数有所上升，三轮范围前为78.7–150.2毫秒、后为79.0–127.5毫秒，有明显重叠；没有取得稳定改善证据，保留为后续优化项，不列作本轮性能收益。没有测出真实用户INP。

## 后续仍需处理的事项

- 繁体目录和面试专题仍加载较大的转换字典。本轮尝试的目录分入口方案没有减少预加载，已撤回；后续须以实际包体与交互结果判断新的拆分方式。
- 生产第三方脚本仍有开销；本轮没有改变广告、统计或同意管理规则。真实用户数据需在未来获准发布后再观察，本次未上线。
- 官方品牌帐号关联及部分报告的真实首次发布日期仍缺证据，沿用此前待核说明，不补造账号或日期。
