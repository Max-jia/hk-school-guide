# 港学荟首页设计方向方案

> 制定日期：2026-10-09  
> 适用范围：首页繁体版、简体版；本阶段只确定设计方向与信息架构，不改业务数据、不部署。

## 1. Design Read

这是一个面向香港家长的教育路线入口页，优先服务“我现在应该先做什么”的决策，而不是展示品牌口号；视觉采用**证据导向的编辑型教育规划工具**语言，沿用港学荟现有的 Pudding editorial 基础，但把重点从“故事卡片”转成“路线地图 + 下一步行动”。

### 使用的设计判断

- `frontend-design-direction`：先明确页面目的、受众、语气、记忆点和约束，再决定布局和动效。
- `design-system`：沿用现有字体、颜色 token、间距和组件习惯，先做一致性审计，不另起一套视觉系统。
- `design-taste-frontend`：把首页当作 redesign，不采用通用的 AI 渐变、三张等宽功能卡或空泛 hero。

## 2. 设计方向

### 目的

让第一次访问的家长在 10 秒内完成两个判断：

1. 我目前处于哪个教育阶段？
2. 我想重点了解 DSE、IB、A-Level，还是还没有决定？

首页的成功不是让用户停留更久，而是让用户进入正确的规划入口、报告或工具。

### 受众

- 正在为幼稚园、小一或小学阶段择校的家长
- 开始考虑中学及高中路线，但尚未理解 DSE、IB、A-Level 差异的家长
- 已经有目标学校，希望快速进入报告、对比或收藏的家长

### 语气

**冷静、清楚、有依据、不过度承诺。**

不使用“保证入读”“最强路线”“一键找到答案”等高风险表达；改用“先厘清路线”“比较适合你的方向”“查看资料与核验状态”。

### 记忆点

把首页的主视觉做成一条可操作的“教育路线地图”：

`幼稚園 → 小一 → 小學 → 中學 → DSE / IB / A-Level → 升學出口`

用户可以从地图节点进入规划，而不是先面对一组互不相关的营销卡片。地图是信息架构的视觉表达，不是装饰性插图。

### 设计参数

- `DESIGN_VARIANCE: 5`：保留现有贴纸和编辑风格，但减少旋转、颜色和卡片数量，提升可信度。
- `MOTION_INTENSITY: 3`：只使用路线节点高亮、卡片进入和按钮反馈；不做滚动炫技或自动播放。
- `VISUAL_DENSITY: 4`：首屏轻量，第二屏开始提供可扫描的阶段和路线选择。

## 3. 视觉系统决策

### 继续使用的现有资产

- `Atlas Grotesk`：导航、正文和操作标签
- `Gooper SemiCondensed`：中文标题和阶段标题
- `Atlas Typewriter`：小型分类标签、数据来源和状态文字
- `--p-*` 颜色 token、现有黑白底色与低饱和背景色
- 现有 `SiteHeader`、`StoryGrid`、`SiteFooter` 组件

本阶段不安装新图标库、不新增字体、不引入渐变背景，也不重做报告页已经稳定的视觉系统。

### 颜色规则

- 黑白作为结构和正文基色。
- 绿色只代表“可以开始/下一步”的主要行动。
- 黄色代表家长需要注意的阶段或选择条件。
- 紫色仅代表路线探索，不作为全站 CTA。
- 红色只用于风险、资料缺失或需要核实的状态。

颜色在首页承担语义，不再让每个区块随意使用一种亮色。

### 形状规则

- 首页主容器使用直角或轻微圆角，延续 editorial 纸张感。
- 主要 CTA 使用现有贴纸按钮语言，但只保留一个主 CTA 形态。
- 路线节点用圆点/短线表达阶段关系，不把每个节点包成独立大卡片。
- 不使用“卡片里再放卡片”的嵌套结构。

## 4. 首页信息架构

### 4.1 Header

保留品牌和繁简切换，导航第一项改为更明确的：

`开始规划`

其余导航继续保留：深度报告、分区盘点、择校工具、学校对比、面试题库、热文。

移动端菜单中把 `开始规划` 置顶，`我的候选` 放在报告和工具之后。

### 4.2 首屏：先看路线，再决定学校

建议文案方向：

> 先看教育路线，再决定学校

辅助说明：

> 从孩子目前的阶段开始，逐步比较学校、收生机制和 DSE、IB、A-Level 路线。资料附来源与核验状态，方便一家人一起做决定。

按钮：

- 主按钮：`开始教育路线规划` → `/cn/planning`
- 次按钮：`我已经有目标学校` → `/reports`

首屏不放统计数字墙、不放大量文章、不放“我们有多少资料”的长说明。先让用户完成入口选择。

### 4.3 路线地图

首屏下方接一条可扫描的路线带：

```text
现在的阶段       小一/小学选择       中学阶段       高中路线              升学出口
幼稚園 ───────→  小學 ─────────→ 中學 ───────→ DSE / IB / A-Level ───→ 大學/專上
```

交互规则：

- 点击阶段节点，进入 `/cn/planning?stage=...`
- 点击 DSE、IB 或 A-Level，进入 `/cn/planning?route=...`
- 未决定路线时，允许从 `尚未决定` 进入比较页，不强迫用户先选路线
- 移动端改为垂直路线，不让文字挤压或横向溢出

### 4.4 阶段入口

用“阶段行”而不是六张等宽营销卡：

1. 幼稚園择校：校網、學費、班級、語言、升小安排
2. 小一自行分配：校網、性別、學額、歷年派位結果
3. 小一統一派位：甲部、乙部、志願順序、滑檔風險
4. 小學階段：學校比較、收藏、轉校與升中準備
5. 中學路線：先提供路线框架，学校资料逐步建设
6. 高中及大學出口：DSE、IB、A-Level 为主，其他出口轻量呈现

每一行只显示“当前问题 + 入口动作”，例如：`查看小一模拟器`，避免在首页复制工具页的复杂逻辑。

### 4.5 三条核心路线

以三条有明确差异的路线说明代替抽象 feature cards：

- **DSE**：香港主流公开考试路线，连接 JUPAS 与本地/海外升学
- **IB**：国际课程路线，重视跨学科、评核结构及海外申请适配
- **A-Level**：科目组合与海外申请弹性较高的路线

每条路线只显示：适合先了解什么、下一步看什么、资料边界。不要在首页把课程细节写成完整百科。

下方提供：`我还未决定，先比较三条路线`。

### 4.6 工具入口

工具区放在路线之后，标题从“热门工具”改成：

> 选择方向后，继续用这些工具

入口顺序：

1. 小一自行分配决策台
2. 小一统一派位模拟器
3. 学校对比
4. 我的候选学校
5. 深度报告

工具入口必须保留当前产品已有的独立筛选逻辑，不在首页复制筛选状态。

### 4.7 内容区与资料可信度

`StoryGrid` 下移，承担搜索和回访，不承担首屏分流。

内容区上方补一条简短可信度说明：

- 资料来源：教育局、学校官方资料及公开数据
- 每项资料显示来源和核验状态
- 报告评级与模拟结果仅供规划参考，不代表录取承诺
- 中学资料正在逐步建设，当前不要暗示覆盖已经完整

## 5. 组件拆分

建议新增以下组件，首页保持 Server Component 为主：

- `src/components/home/PlanningHero.tsx`
- `src/components/home/EducationRouteMap.tsx`
- `src/components/home/StageEntryList.tsx`
- `src/components/home/CoreRouteCards.tsx`
- `src/components/home/FeaturedTools.tsx`
- `src/components/home/CoverageTrustNote.tsx`

只有路线高亮和轻量 hover/focus 状态需要 Client Component；不为首页引入全局状态。

## 6. 响应式方案

### Desktop

- 最大内容宽度沿用 `1280px`
- 首屏文案宽度控制在约 620px
- 路线地图横向展开，阶段入口为两列或单列带分组的行
- 主 CTA 与次 CTA 同行，但主 CTA 明显更强

### Mobile

- Header 保持单行，菜单中把开始规划置顶
- Hero 文案左对齐，按钮上下排列并保证触控高度
- 路线地图改为纵向节点，所有中文完整换行
- 阶段入口单列，不使用需要横向拖动才能看懂的卡片
- DSE、IB、A-Level 纵向排列，先显示差异，再显示入口

必须重点验收：简体/繁体切换后，长标题、路线标签和 CTA 不溢出、不重叠。

## 7. 开发顺序

### 第一步：只做首页骨架

- 新增 Hero、路线地图、阶段入口
- 暂时保留现有 StoryGrid、数据说明和 Footer
- 不改报告 JSON、工具逻辑和付费授权

验收：桌面/手机、繁体/简体、键盘焦点、所有入口 URL。

### 第二步：接入 `/cn/planning`

- 读取 `stage` 和 `route` query
- 显示对应的下一步任务
- 先覆盖 K3 → P1 → 小学 → DSE 的纵向样板
- IB/A-Level 先覆盖路线比较和下一步导航，不急于做完整数据库

验收：从首页每个节点进入后，用户能明确知道下一步做什么。

### 第三步：接工具和收藏

- 首页工具入口接入现有 P1、对比和 shortlist
- 收藏状态不在首页重复实现
- 从报告、对比、规划页返回时保留用户当前路线参数

验收：真实点击路径、空状态、回退、移动端操作。

### 第四步：内容与分析

接入这些事件：

- `planning_start`
- `stage_selected`
- `route_selected`
- `planning_result_viewed`
- `tool_opened_from_home`
- `report_opened_from_home`
- `shortlist_started`

验收：事件只记录必要的匿名路径信息，不记录儿童姓名、联系方式或详细家庭身份资料。

## 8. 首页完成标准

- 首屏能回答“港学荟是什么”和“我下一步去哪”
- 用户不选学校，也能从阶段或路线开始
- DSE、IB、A-Level 是视觉和产品主线
- 其他出口有入口但不抢主视觉
- 不虚构中学资料覆盖范围
- 现有报告、P1 模拟器、学校对比、shortlist 入口均可达
- 繁简中文、桌面/手机无溢出和重复显示
- `npm run lint`、`npm run typecheck`、`npm run build` 通过后才进入下一步
- 本地浏览器逐项点击验收后，才讨论部署

## 9. 本阶段明确不做

- 不先做完整路线测验或复杂 AI 推荐
- 不把首页改成纯营销 landing page
- 不新增大型图片、渐变背景或第三方 UI 依赖
- 不复制竞品文案或样式
- 不以“报告数量”取代路线规划价值
- 不在资料未齐全前宣称中学路线已经完整覆盖
