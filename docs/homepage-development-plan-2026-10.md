# 港学荟首页改造开发计划

> 目标：把首页从「报告/工具目录」改成「教育路线规划入口」。  
> 范围：先改首页信息架构和用户分流，不立即重做所有内页。  
> 核心路线：DSE、IB、A-Level；其他出口只作为轻量备用说明。  
> 开发原则：先做一个完整可用的纵向入口，再逐步扩充中学资料；不修改报告 JSON，不突破付费授权边界。

## 1. 当前首页问题

当前首页主要是：

```text
Header
→ 已经有心仪学校？浏览报告
→ 还在纠结？进入择校工具
→ 精选报告
→ 热文
→ 数据说明
```

这套结构适合「找一所学校」，但不适合新的教育路线产品，主要问题是：

1. 用户不知道港学荟是否能帮助规划 DSE/IB/A-Level。
2. 首页缺少「孩子当前阶段」入口。
3. 报告、工具、热文是按内容类型排列，不是按家长决策顺序排列。
4. P1工具很强，但首页没有把它放入更大的教育路线中。
5. 中学资料尚未完整，若直接宣传完整路线，会造成产品承诺过度。
6. 首页数据数字是静态文案，未来需改为数据版本或统一数据源。

## 2. 首页的新任务

首页只承担五个任务：

1. 让用户在 5 秒内知道港学荟是什么。
2. 让用户选择「当前阶段」或「目标路线」。
3. 把用户带到下一步，而不是让用户在报告和文章之间迷路。
4. 让用户信任资料来源和方法边界。
5. 将用户导向现有报告、工具、收藏和比较产品。

首页不承担：

- 解释所有教育制度细节
- 展示所有学校
- 一次性推荐唯一学校
- 直接替代升学顾问
- 在中学资料不足时承诺完整路线结果

## 3. 首页目标用户分流

首页首屏提供两个主分流维度：

### 3.1 按当前阶段进入

- 幼稚园择校
- 准备小一
- 小学阶段
- 准备中一
- 中学阶段
- 高中/大学规划

### 3.2 按路线进入

- DSE
- IB
- A-Level
- 尚未决定

用户可以只选择一个维度，也可以先选阶段再选路线。

## 4. 建议首页结构

### Section 0：Header

保留现有港学荟品牌和简繁切换，但导航顺序调整为：

1. 开始规划
2. 深度报告
3. 择校工具
4. 学校对比
5. 我的候选
6. 热文

「开始规划」应成为第一导航入口，不再把「深度报告」作为唯一核心入口。

### Section 1：主 Hero —— 先规划路线，再选择学校

推荐文案结构：

```text
港学荟
先看教育路线，再决定学校

从幼稚园、小学到中学，围绕 DSE、IB、A-Level，
把下一次申请、选校和升学决定拆成可执行步骤。

[开始教育路线规划]  [我已经有目标学校]
```

Hero 下方显示三个信任标签：

- 香港学校公开资料整理
- 来源与核验日期可查看
- 不承诺录取概率

第二个按钮直接进入 `/cn/reports`，服务已经知道目标学校的用户。

### Section 2：当前阶段入口

标题：

> 你现在最需要解决哪一步？

六张卡片：

1. 幼稚園择校
2. 小一自行分配
3. 小一统一派位
4. 小学阶段规划
5. 中学路线选择
6. 高中及大学出口

每张卡只显示：

- 当前核心问题
- 推荐的一个主产品
- 是否已有完整资料

例如：

```text
小一统一派位
志愿怎么排，保底放哪里？
进入统一派位选校台 →
```

### Section 3：三条核心路线

标题：

> 你倾向哪条升学路线？

三张主卡：

#### DSE

本地学校、选科、DSE、JUPAS与大学出口。

#### IB

国际课程、PYP/MYP/DP衔接及海外升学方向。

#### A-Level

IGCSE、AS、A-Level、选科及海外申请方向。

第四个较轻量的入口：

```text
还没有决定？
先比较路线，不急着选定。
```

重要提示：当前中学资料未完整时，路线卡应标记「路线框架已开放，中学学校资料持续建设中」，避免过度承诺。

### Section 4：路线规划演示

标题：

> 规划会怎样帮助你？

用一个匿名示例展示：

```text
K3家庭
→ 选择 DSE 为主路线
→ 确认小一申请阶段
→ 比较目标学校
→ 建立收藏清单
→ 使用计分器和统一派位模拟器
→ 记录下一次申请时间
```

该区域不是展示复杂功能，而是让用户理解「路线 → 决策 → 工具」的关系。

### Section 5：当前可以立即使用的工具

只展示三到四个最相关产品：

1. 小一计分／自行分配工具
2. 统一派位选校表决策台
3. 学校对比
4. 我的候选

不要把所有工具平铺在首页。首页产品卡应回答：

```text
这个工具解决什么问题？
现在适不适合我？
点进去后会得到什么？
```

### Section 6：精选报告和路线内容

保留现有 StoryGrid，但从首页首屏下移到路线和工具之后。

精选内容分成：

- 小学深度报告
- 幼稚園深度报告
- DSE/IB/A-Level路线文章
- 申请时间线和制度攻略

未来中学内容加入前，不使用看似完整的「全学段报告」措辞。

### Section 7：可信度和覆盖边界

首页下方集中说明：

- 资料来自哪些公开来源
- 哪些是官方事实
- 哪些是平台分析
- 数据什么时候核验
- 当前覆盖幼稚園和小学到什么程度
- 中学资料哪些部分仍在建设

这部分要避免只写「数据多」，而要让用户知道资料能否支持当前决定。

### Section 8：低干扰 Footer CTA

底部保留三个动作：

- 开始规划
- 浏览报告
- 使用工具

不在 Footer 里重复大段路线说明。

## 5. 首页交互流程

### 5.1 未知用户

```text
首页
→ 选择当前阶段
→ 选择主路线/尚未决定
→ 进入规划工作台
→ 推荐现有工具或报告
```

### 5.2 已知目标学校用户

```text
首页
→ 搜索或浏览学校
→ 报告页
→ 收藏
→ 两校比较
→ 进入相应阶段工具
```

### 5.3 已在小一申请期用户

```text
首页
→ 小一自行分配/统一派位
→ 直接进入对应决策台
→ 收藏候选学校
→ 生成/保存志愿方案
```

首页不能阻塞已有用户；旧的报告和工具路径必须继续可达。

## 6. 首页数据和组件计划

### 6.1 新增组件

- `PlanningHero`
- `StageEntryGrid`
- `RouteCards`
- `PlanningDemo`
- `FeaturedTools`
- `CoverageAndTrust`

### 6.2 新增共享配置

```ts
type EducationRoute = "dse" | "ib" | "a-level" | "undecided";
type PlanningStage =
  | "kindergarten"
  | "primary-one"
  | "primary"
  | "secondary-entry"
  | "secondary"
  | "post-secondary";
```

路线卡、阶段卡、导航、SEO metadata 和分析事件统一使用配置，不在 JSX 中重复硬编码。

### 6.3 路径设计

先建立以下路径：

- `/cn/planning`
- `/cn/planning?stage=primary-one`
- `/cn/planning?route=dse`
- `/cn/tools/p1-discretionary`
- `/cn/tools/p1-simulator`
- `/cn/reports`
- `/cn/compare`
- `/cn/shortlist`

路线详情页可以后置，首页先使用路线卡进入规划入口。

## 7. 开发阶段和验收标准

### Phase 0：产品和数据契约

工作：

- 确认首页文案、路线命名和阶段命名
- 确认当前覆盖边界
- 建立 route/stage 配置
- 盘点所有现有入口和链接
- 设计分析事件

验收：

- 不出现「中学资料已完整」等过度承诺
- DSE/IB/A-Level 三条主线定义一致
- 简体和繁体文案结构一致

### Phase 1：首页结构重做

工作：

- 新 Hero
- 当前阶段入口
- 三条路线卡
- 工具入口
- 可信度和覆盖说明

验收：

- 5 秒看懂网站定位
- 10 秒能选择阶段或路线
- 目标学校用户仍可直接进入报告
- 小一用户最多两次点击进入对应工具

### Phase 2：规划入口页

工作：

- `/cn/planning`
- 当前阶段选择
- 路线选择
- 轻量家庭资料
- 输出路线卡和下一步

验收：

- 不登录也能完成首次规划
- 不强迫用户决定路线
- 能把结果导向现有报告、工具、比较和收藏
- 不读取或暴露付费正文

### Phase 3：视觉和移动端验收

重点检查：

- 375px移动端首屏
- 768px平板
- 桌面端宽屏
- 繁体/简体切换
- 菜单和按钮位置
- 卡片文字长度
- 锚点跳转
- 键盘可操作和焦点状态

### Phase 4：线上数据和转化验证

建议埋点：

- `planning_start`
- `stage_selected`
- `route_selected`
- `planning_result_viewed`
- `tool_opened_from_home`
- `report_opened_from_home`
- `shortlist_started`

先观察两周，再决定是否加重会员、路线报告或咨询 CTA。

## 8. 首页视觉方向

保留现有港学荟的纸张、贴纸、轻微旋转和编辑感，但首页第一视觉要从「内容杂志」转为「路线工作台入口」。

建议视觉层级：

1. Hero：大面积留白，突出路线规划主标题。
2. 阶段卡：清楚、稳定、低装饰，保证快速选择。
3. 路线卡：DSE/IB/A-Level使用三种稳定色彩区分。
4. 工具卡：比路线卡更实用，突出操作结果。
5. StoryGrid：保留原有编辑感，作为内容证明，不再承担主导航任务。

不要在首页同时使用过多不同颜色、旋转角度、贴纸和入口，否则路线决策会被视觉装饰淹没。

## 9. SEO与内容边界

首页应围绕以下主题建立标题和描述：

- 香港教育路线规划
- DSE、IB、A-Level路线比较
- 香港幼稚園、小學择校
- 小一派位和学校决策工具

但不能在尚无中学数据时写：

- 全港完整中学资料库
- 任何路线保证升学
- 某条路线一定更好

页面结构化数据保留 WebSite；路线和阶段页面成熟后，再加 ItemList 或 FAQ，避免首页一次塞入过多结构化内容。

## 10. 第一阶段不做什么

- 不在首页嵌入完整问卷
- 不在首页展示所有学校
- 不立即建设完整大学数据库
- 不把职业教育做成并列主路线
- 不直接改动报告 JSON
- 不改动付费墙和授权逻辑
- 不为了首页改造重做报告正文视觉

## 11. 建议的第一轮开发顺序

1. 先完成首页信息架构和文案草图。
2. 再做 `PlanningHero`、阶段入口和路线卡。
3. 接入现有 P1 工具、报告、比较和收藏。
4. 在本地验收繁简、移动端和关键点击路径。
5. 再开发 `/cn/planning` 规划入口。
6. 最后根据真实点击数据调整首页 CTA和产品排序。

## 12. 第一轮完成定义

第一轮不是「把所有教育路线做完」，而是完成一个可验证的首页入口：

```text
家长进入首页
→ 看懂港学荟做什么
→ 选择当前阶段或 DSE/IB/A-Level
→ 进入正确的规划入口
→ 使用现有报告/工具/收藏
→ 清楚知道资料覆盖边界和下一步
```

如果这个闭环成立，再继续建设中学数据库和三条路线的深层产品；如果闭环不成立，不应急着扩充内容规模。
